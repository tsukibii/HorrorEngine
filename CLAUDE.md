# HorrorStudio: notes for Claude

One project that makes short (2.5 to 3 hour) first-person horror games, one after another. Every game lives in this
project (docs/STUDIO.md), so shaders, systems and tools are built once. **The games ship from Godot** (DECISIONS
2026-10-29, night: "Godot 100% for this project now"): the desk's story is exported as a Godot 4.7 project
(docs/GODOT_PLAN.md, docs/GODOT_EXPORT.md, `tools/godot_export.py`). The Unreal side was removed on 2026-10-30
(DECISIONS, evening: the `.uproject`, `Source/`, `UnrealPlugins/`, UnrealClaude, the importer, its docs; all in git
history before that); its numbers (UltraVHS's measures, Light Kit's curves) are what the Godot side matches, and
UltraVHS's numpy reference lives on in `tools/ultravhs/`. **A game can also be built in Godot itself** (DECISIONS
2026-10-30, night: "Director-Godot"): the HorrorStudio Director plugin's nodes and dock (docs/GODOT_DIRECTOR.md),
compiled at play into the same runtime. **Lines are text, not voice**
(same day): no takes' audio in the export; a typewriter blip only after a playtest, if the user wants it.

**The split:**
- **The user** writes rough stories and makes the MetaHumans, the takes (MiniMax, Japanese voice, close-up face
  videos, 10 s or less each) and the face mocap, and fine-tunes.
- **Claude** is co-lead engineer and assistant artist: it turns stories into `Content/Games/<Game>/story.json`
  (docs/STORY_FORMAT.md), builds and checks the greybox, the systems and the animation passes, and reviews every
  frame that matters by measurement.

Games go **spine first** (the actor scenes, timed by their takes), then the player's tasks stitched between them
(docs/PIPELINE.md). **Everything is plotted, blocked (bodies, shots, events) and reviewed in the director's desk
(`tools/director/`) before it's exported to Godot:** the desk's storyboard and glTF blocking are the reference the
game must match. Directing craft: docs/DIRECTING.md.

## Start every session with

1. `docs/DECISIONS.md`: the user's answers. They override everything, newest first. Then `docs/CONTINUE.md`: where
   the last session stopped and what could come next.
2. `python tools/story.py --game <Game> notes`: what the user left on the director's desk. Answer with a note
   (`by: claude`) and tick what you've done.
3. `docs/games/<Game>.md` for the game in progress.
4. **Ask the user what they are doing now** (docs/PIPELINE.md is a menu, not a sequence), then do only that step.
   Don't start the next one on your own.

## Rules

- **Text is the truth.** Change story.json and export again; never hand-edit what the export writes (a new version is
  written each time). The user's hand work lives in `Content/Studio/`, `Content/Games/<G>/Art`, the `art` fields, and
  the lighting they set up by hand in a Godot version's levels (copied to the next).
- **Never use a word the format doesn't have.** Grow the runner, the check and STORY_FORMAT.md in one commit.
- **Timing is elastic:** never anchor anything to an absolute scene time. Cues ride on clip edges, bodies on clip
  lengths. A clip is one take of 10 s or less, and every cut has a seam (TRICKS.md §1).
- **A game never references another game's folder.** Shared things move to `Content/Studio/`.
- **Keep context small:**
  - `story.py flow | show <id> | rooms | notes` instead of reading story.json
  - `tail` on outputs
  - contact sheets, not single frames
  - read the review JSON first
- **First person: the camera is the player.** Only what their eye can see from where they can stand: one lens
  (`game.fov`), shot sizes by distance, `stance` for height, `push` to lean in. Never a `fov` on a clip
  (DIRECTING.md §1).
- **Assets are CC0 or ours.** Place library props by name (`cc0.py props`, `story.py art`), texture rooms with `look`
  (docs/ASSETS.md §4), fetch with `cc0.py fetch`; anything not CC0 (Mixamo, Epic, MetaHumans) stays in the user's
  own project and never in a shared file.
- **You can't judge the scare; you can judge the frame.** Measure (the shot review, MOTION), say what you think the
  mood needs, and let the user decide in play.
- **One step per commit, pushed.** The user changes course quickly. When something takes a second try, write the
  lesson in docs/LESSONS.md first.
- **The user's machine is Omarchy (Arch Linux, Hyprland), RTX 3090,** with Godot 4.7, and the project is this folder. Commands for the user are bash with full paths; Python is uv. Never `pkill -f` or `pgrep -f`
  in the same command line that names the process (it matches and kills your own shell): find the PID in one
  command, kill it in the next.
